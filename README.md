# sus

Я честно устал страдать над strace/ltrace очередных бинарей сомнительного качества, поэтому ~~клод~~ написал `sus`
через eBPF и после завершения выдаёт отчёт — что открывал, что писал, куда
лез по сети, пытался ли закрепиться или повысить права. По желанию заодно
сажает процесс в песочницу, чтобы ничего лишнего не натворил.

Может, кому-то ещё пригодится.

```
sudo sus -isolate -no-net -timeout 60s -keep ./loot -o auto ./sample
```

## Что он делает

- Строит дерево процессов с реальными argv, а не просто список PID.
- Пишет кто что читал/писал/удалял, с sha256 и определением ELF/скрипта/setuid
  у записанных файлов.
- Ловит сеть: `connect`, `bind`, `sendto`, и DNS-имена через `getaddrinfo`
  (не обратный DNS, а то имя, которое программа реально запросила).
- Отдельно замечает `rename`, `chmod`, `symlink`, `mount`, `ptrace`, `setuid`,
  загрузку модулей ядра, `memfd_create`, разведку через `stat`/`access`.
- В конце — вердикт (`none`/`low`/`medium`/`high`) по категориям находок и
  блок индикаторов (домены, IP, хеши) для копирования.
- По флагу `-isolate` запускает команду в песочнице: свои namespace'ы,
  read-only система, поддельный home с приманками вместо настоящих ключей,
  без capabilities, с seccomp-фильтром — а трассировка всё равно работает,
  потому что сидит в ядре снаружи песочницы.
- `-no-net` обрубает сеть, но попытки подключений и имена всё равно видны —
  узнаёшь адрес C2, не связываясь с ним.
- `-o` сохраняет отчёт одним HTML-файлом: дерево, таймлайн, находки, IOC с
  кнопками копирования — без сервера и зависимостей.

## Зависимости и сборка

Нужно:

- Linux с BTF в ядре (`/sys/kernel/btf/vmlinux` должен существовать), x86-64;
- `clang`, `llvm`, `libbpf-dev`, `bpftool`, `go` (1.25+ — `go.mod` требует именно столько), `make`;
- для `-isolate` ещё `bubblewrap` и `setpriv` (пакет `util-linux`, он почти
  везде уже есть).

```bash
sudo apt install -y clang llvm libbpf-dev golang-go make linux-tools-common linux-tools-$(uname -r) bubblewrap
git clone https://github.com/3xh4u573d/sus.git
cd sus
make
sudo ./sus curl -s https://example.com
```

`make` по шагам: `bpftool btf dump` снимает типы твоего ядра в
`bpf/vmlinux.h`, `go get` тянет `cilium/ebpf`, `go generate` гоняет
`bpf2go` (компилирует `bpf/sus.bpf.c` и генерирует Go-обвязку), `go build`
собирает бинарь.

Поставить в систему с автодополнением:

```bash
sudo make install
```

## Запуск

```
sudo sus [флаги] [--] команда [аргументы...]
```

Команда запускается от имени того, кто вызвал `sudo` (`$SUDO_UID`), а не от
root — иначе установщик увидел бы не тот `$HOME` и не те права. Для команд
из пользовательского PATH: `sudo env "PATH=$PATH" sus npm install`.

## Флаги

| Флаг | Что делает |
|---|---|
| `-no-net` | пустое сетевое пространство: интернета нет, но попытки подключений и запрошенные имена видны |
| `-isolate` | песочница (нужен `bubblewrap`), см. ниже |
| `-ro путь`, `-rw путь` | с `-isolate`: открыть ещё путь на чтение или запись (можно несколько раз) |
| `-no-canary` | с `-isolate`: не класть в поддельный home приманки |
| `-timeout 60s` | убить команду и всё, что она запустила, по таймеру |
| `-mem 512M`, `-pids 200` | лимиты памяти и числа процессов через cgroup |
| `-keep dir` | скопировать записанные и запущенные не-системные файлы в `dir` под именем sha256 |
| `-o файл.html` | автономный HTML-отчёт; `-o auto` сам подберёт имя |
| `-w`, `-watch` | печатать события сразу, по ходу работы |
| `-t`, `-timeline` | хронологический список событий вместо группировки по процессу |
| `-r`, `-resolve` | обратный DNS для IP (делается после запуска, создаёт свой трафик, поэтому по умолчанию выключен) |
| `-all` | показать и системный шум (`/usr/lib`, `/proc`, `/dev`) |
| `-json` | отчёт в JSON |
| `-no-hash` | не считать хеши файлов |
| `-no-pager`, `-no-color` | без `less`, без цветов |
| `-completion zsh\|bash` | вывести скрипт автодополнения |
| `-v` | отладка |

## Что в отчёте

- **Вердикт и находки по категориям**: persistence, credential access,
  privilege escalation, defense evasion, discovery, execution, system
  change. Это эвристики по путям и вызовам — отсутствие находок не значит,
  что файл безопасен.
- **Запущенные бинари**: sha256 и аномалии — запуск из `/tmp`, из скрытого
  пути, из файла-дескриптора (fileless), из файла, который программа сама
  создала или уже удалила.
- **Файлы**: чтение, запись (с sha256 и определением ELF/скрипта/setuid),
  удаление, `rename`, `mkdir`, `chmod`, `symlink`, разведка через
  `stat`/`access`. Системный шум сворачивается в одну строку.
- **Сеть**: `connect`, `bind`, `sendto`, запросы `getaddrinfo` (и неудачные
  тоже) с именами рядом с адресами. Метки на `docker.sock` и `ssh-agent`.
- **Поведение**: `ptrace`, `setuid`, `mount`, `memfd_create`, загрузка
  модулей, проверки на VM (`/sys/class/dmi/id`) и на дебаггер (`TracerPid`),
  возня с логами и историей.
- **IOC**: домены, публичные IP, хеши и пути файлов — с кнопкой копирования
  в HTML.
- **Окружение**: имена подозрительных переменных, которые унаследовала
  команда (без значений — eBPF не видит, кто читает переменную из памяти,
  только что ей передали при старте).
- **Итог**: `exit N`, `killed by SIGSEGV`, сработавший таймаут или лимит
  памяти. Всё, что осталось висеть после выхода команды, убивается.

## Изоляция (`-isolate`)

cgroup — вообще не про безопасность, тк выйти из неё можно через root, файлы хоста (твой `~/.ssh`), сокеты
(`dbus`, `docker.sock`, `ssh-agent`), дыры в ядре. `-isolate` это закрывает,
а команда остаётся в той же cgroup, так что трассировка не ломается:

```bash
sudo sus -isolate -no-net -timeout 60s -mem 512M -pids 200 -keep ./loot -o auto ./sample
```

Что получает команда:

- свои namespace'ы (pid, ipc, uts, cgroup, с `-no-net` ещё и network);
- запуск без root и без единой capability, с `no_new_privs`;
- `/usr` и `/etc` только на чтение, нет `/sys` (нет доступа к cgroup-дереву),
  нет `/run/user` (нет шины сессии, ssh-agent, иксов);
- вместо настоящего home — поддельный, с приманками (`id_rsa`,
  `.aws/credentials`, `Login Data` браузера); если программа их читает —
  это сразу видно в находках;
- чистое окружение, без `DBUS_*`, `SSH_AUTH_SOCK`, `DISPLAY`;
- seccomp-фильтр против `bpf`, `io_uring`, `unshare`, `setns`, создания
  новых namespace через `clone` и прочего. `ptrace`/`mount`/`setuid` не
  блокируются специально — без capability они и так ничего не дадут, а
  попытку отчёт всё равно покажет (запрет через seccomp её бы скрыл);
- сама запускаемая программа и файлы из аргументов видны только на чтение,
  даже если лежат в `/tmp` — поэтому самоудаляющийся вредонос не сможет
  стереть себя, и бинарь останется для анализа.

Честно: это сужает поверхность атаки, а не заменяет VM — дыра в ядре,
которую seccomp не ловит, обойдёт всё это. Недоверенное всё равно есть смысл гонять в VM. 
Без `-no-net` сеть общая, и песочница видит loopback-службы
хоста — я по кд добавляю с `-no-net`.

## Как это работает

```
sus (Go, root)                                  ядро
---------------                                 ----
создаёт cgroup /sys/fs/cgroup/sus-PID
пишет id cgroup в map `target`
запускает команду прямо в неё        -->        все потомки автоматически внутри
                                                 sched_process_exec, fexit на
                                                 syscall-обёртках, uprobe на
                                                 getaddrinfo
                                                 -> если cgroup_id == target:
                                                    событие в ring buffer
читает ring buffer   <---------------------------
собирает отчёт после завершения
```

Фильтрация по cgroup, а не PID — нет гонки между стартом процесса и
добавлением его в список. Запуски ловятся через `tp_btf/sched_process_exec`
(argv читается из `task_struct->mm->arg_start` через CO-RE), системные
вызовы через `fexit` на `__x64_sys_*` (виден код возврата, буферы ещё целы).
Не через `tracepoint/syscalls/sys_enter_*` — на ядрах, под которые это
писалось, они молчат для процессов, запущенных через `vfork` (так делают Go,
Python и часть шеллов), и события корневого процесса пропадали.

## Ограничения

- Только x86-64.
- Относительные пути с нестандартным `dirfd` разрешаются неточно.
- Не покрыто: старый `open`, `chown`, `sendmsg`, `listen`, io_uring, DNS
  мимо glibc (свой резолвер в Go, статические бинари, musl) — для них
  остаётся `-r`.
- Хеши и `-keep` берутся по состоянию файла после выхода команды; то, что
  она успела удалить до этого, не восстановить.
